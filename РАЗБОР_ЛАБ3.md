# Разбор лабораторной №3 простыми словами

Это шпаргалка для себя, не часть приложения. Читать лучше по порядку:
сначала общая картина, потом путь одного запроса, потом файлы и термины.

---

## 1. Что вообще делает программа

Это сайт со ссылками. На нём есть страницы:

- `/` — список ссылок и поиск;
- `/manage` — добавить, изменить и удалить ссылку;
- `/contacts` — контакты;
- `/docs` — Swagger, страница для проверки API.

Сами ссылки хранятся в базе данных PostgreSQL. Сайт не лезет в базу напрямую:
он отправляет HTTP-запросы на сервер (API), а сервер уже работает с базой.

В лабораторной №3 сделаны четыре вещи:

1. Данные переехали из памяти в PostgreSQL.
2. Для работы с базой используется ORM SQLAlchemy.
3. Приложение и база запускаются в Docker через docker-compose.
4. API защищено ключом `X-API-Key`.

---

## 2. Общая картина

```
Браузер (HTML + CSS + JS)
        │
        │ HTTP-запрос, JSON, заголовок X-API-Key
        ▼
FastAPI (Python)
        │
        │ вызывает метод сервиса
        ▼
LinkService — правила приложения (например, лимит 50)
        │
        │ вызывает репозиторий
        ▼
SqlAlchemyLinkRepository
        │
        │ SQL-запросы
        ▼
PostgreSQL, таблица links
```

Можно представить как ресторан:

- браузер — посетитель;
- FastAPI — официант, принимает заказ;
- LinkService — менеджер, проверяет правила;
- репозиторий — кладовщик, который берёт и кладёт товар;
- PostgreSQL — склад;
- Docker — здание, в котором всё это работает.

Docker не является ещё одним слоем программы. Это просто способ упаковать
backend и базу и запустить их одной командой.

## 3. Что происходит, когда нажимаешь «Добавить»

Допустим, на странице `/manage` ввели название `ВК` и адрес `https://vk.com`.

### Шаг 1. Форма

В `static/manage.html` есть форма:

```html
<form id="form">
  <input type="text" id="title" ...>
  <input type="url" id="url" ...>
  <button type="submit">Добавить</button>
</form>
```

### Шаг 2. JS перехватывает отправку

В `static/js/manage.js`:

```js
form.onsubmit = async function (event) {
  event.preventDefault();
  const ok = editingId === null
    ? await addLink(titleInput.value, urlInput.value)
    : await updateLink(editingId, titleInput.value, urlInput.value);
  ...
};
```

`event.preventDefault()` отменяет обычную перезагрузку страницы.
Дальше вызывается `addLink()`.

### Шаг 3. JS отправляет HTTP-запрос

В `static/js/api.js`:

```js
async function addLink(title, url) {
  const response = await apiFetch("/api/links", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: title, url: url }),
  });
  ...
}
```

То есть браузер делает запрос:

```
POST /api/links
Content-Type: application/json
X-API-Key: student-key

{"title": "ВК", "url": "https://vk.com"}
```

`fetch` — встроенная функция браузера для HTTP-запросов.
`JSON.stringify` превращает JS-объект в строку JSON.

### Шаг 4. FastAPI проверяет ключ

В `app/presentation/api.py`:

```python
router = APIRouter(
    prefix="/api/links",
    tags=["Links"],
    dependencies=[Depends(check_api_key)],
)
```

`dependencies=[Depends(check_api_key)]` значит: перед любым методом этого
роутера FastAPI вызовет `check_api_key()`.

В `app/presentation/security.py`:

```python
API_KEY = os.getenv("API_KEY", "student-key")

def check_api_key(key: str | None = Security(api_key_header)):
    if key != API_KEY:
        raise HTTPException(status_code=401, detail="Неверный API-ключ")
    return key
```

Если ключ неверный или его нет — ответ `401 Unauthorized`.
Если всё хорошо — FastAPI идёт дальше.

### Шаг 5. FastAPI вызывает функцию создания

```python
@router.post("", response_model=LinkOut, status_code=201, summary="Добавить ссылку")
def create_link(body: LinkIn, service: LinkService = Depends(get_service)):
    return service.create(body.title, body.url)
```

- `body: LinkIn` — FastAPI читает JSON из запроса и проверяет его по схеме.
- `service: LinkService = Depends(get_service)` — FastAPI сам создаёт/берёт сервис.
- `status_code=201` — код ответа «создано».
- `response_model=LinkOut` — что именно вернуть в JSON.

Схемы лежат в `app/presentation/schemas.py`:

```python
class LinkIn(BaseModel):
    title: str = Field(max_length=200)
    url: str = Field(max_length=500)

class LinkOut(BaseModel):
    id: int
    title: str
    url: str
```

`LinkIn` — что принимаем. `LinkOut` — что отдаём. Если `title` длиннее
200 символов, FastAPI сам вернёт `422`.

### Шаг 6. Сервис проверяет правила

В `app/application/services.py`:

```python
def create(self, title: str, url: str) -> Link:
    if self.repository.count() >= self.limit:
        raise StorageLimitError("Достигнут лимит в 50 записей")
    return self.repository.add(title, url)
```

Здесь бизнес-логика: нельзя хранить больше 50 ссылок.
Если лимит достигнут — исключение `StorageLimitError`, которое `main.py`
превращает в ответ `409 Conflict`.

### Шаг 7. Репозиторий пишет в базу

В `app/infrastructure/repository.py`:

```python
def add(self, title: str, url: str) -> Link:
    with SessionLocal() as session:
        model = LinkModel(title=title, url=url)
        session.add(model)
        session.commit()
        session.refresh(model)
        return to_link(model)
```

- `SessionLocal()` — подключение/сессия к базе.
- `LinkModel(...)` — Python-объект, который соответствует строке таблицы.
- `session.add` — «запомни, что надо вставить».
- `session.commit` — реально выполнить `INSERT`.
- `session.refresh` — прочитать из базы `id`, который выдал PostgreSQL.
- `to_link` — превратить объект базы в обычный `Link` из domain.

### Шаг 8. SQLAlchemy делает SQL

Модель описана в `app/infrastructure/models.py`:

```python
class LinkModel(Base):
    __tablename__ = "links"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    url: Mapped[str] = mapped_column(String(500))
```

SQLAlchemy превращает `session.add(...)` примерно в:

```sql
INSERT INTO links (title, url) VALUES ('ВК', 'https://vk.com') RETURNING id;
```

### Шаг 9. Ответ уходит обратно

FastAPI берёт `Link`, проверяет его по `LinkOut` и отправляет JSON:

```json
{"id": 3, "title": "ВК", "url": "https://vk.com"}
```

Браузер получает ответ. `manage.js` очищает форму и вызывает `render()`.
`render()` снова запрашивает список через `GET /api/links` и перерисовывает
`<ul>`.

Вот и весь путь одного добавления.

## 4. Файлы: кто за что отвечает

### Точка входа

**`main.py`**

- создаёт приложение `FastAPI`;
- при старте ждёт PostgreSQL и создаёт таблицы;
- подключает роутер с API;
- отдаёт HTML-страницы `/`, `/manage`, `/contacts`;
- отдаёт статику `/static/...`;
- превращает ошибки `LinkNotFoundError` в `404`, `StorageLimitError` в `409`;
- имеет `/health` для проверки, что сервер жив.

`lifespan` — это функция, которая выполняется при запуске и остановке
приложения. В ней стоит цикл из 10 попыток подключиться к базе, потому что
PostgreSQL в Docker может стартовать чуть медленнее.

### Domain — самое ядро

**`app/domain/entities.py`**

```python
@dataclass
class Link:
    id: int
    title: str
    url: str
```

Просто описание ссылки. Никакой базы, никакого FastAPI. Это «что такое
ссылка» в нашей программе.

**`app/domain/exceptions.py`**

Два своих исключения: `LinkNotFoundError` и `StorageLimitError`.
Они нужны, чтобы сервис мог сказать «ссылки нет» или «лимит», не зная,
как это будет показано пользователю.

### Application — правила

**`app/application/interfaces.py`**

Абстрактный класс `LinkRepository`. Это список методов, которые обязан
уметь любой репозиторий: `add`, `get`, `list`, `update`, `delete`, `count`.

Сам по себе он ничего не делает. Это «договор».

**`app/application/services.py`**

`LinkService` — правила приложения:

- нельзя больше 50 ссылок;
- если ссылки нет — ошибка;
- остальное просто передаёт в репозиторий.

Важно: сервис не знает, где хранятся данные — в памяти или в PostgreSQL.
Он работает с интерфейсом.

Именно поэтому в лабе №2 можно было иметь `InMemoryLinkRepository`,
а в лабе №3 — `SqlAlchemyLinkRepository`, и сервис не пришлось переписывать.

### Infrastructure — работа с базой

**`app/infrastructure/database.py`**

- читает адрес базы из `DATABASE_URL`;
- создаёт `engine` — подключение к PostgreSQL;
- создаёт `SessionLocal` — фабрику сессий;
- `Base` — базовый класс для моделей;
- `create_tables()` — создаёт таблицы по моделям.

**`app/infrastructure/models.py`**

`LinkModel` — описание таблицы `links` для SQLAlchemy.

**`app/infrastructure/repository.py`**

`SqlAlchemyLinkRepository` — реальные операции с базой:

- `add` — INSERT;
- `get` — SELECT по id;
- `list` — SELECT всех;
- `update` — SELECT, изменение, UPDATE;
- `delete` — SELECT, DELETE;
- `count` — COUNT(*).

`to_link()` переводит `LinkModel` (объект базы) в `Link` (объект domain),
чтобы верхние слои не зависели от SQLAlchemy.

### Presentation — общение с внешним миром

**`app/presentation/api.py`**

Роуты API:

| Метод | URL | Что делает |
|---|---|---|
| GET | `/api/links` | список |
| GET | `/api/links/{id}` | одна |
| POST | `/api/links` | создать |
| PUT | `/api/links/{id}` | изменить |
| DELETE | `/api/links/{id}` | удалить |

**`app/presentation/schemas.py`**

Pydantic-схемы `LinkIn` и `LinkOut`. Проверяют вход и формируют выход.

**`app/presentation/security.py`**

Проверка ключа `X-API-Key`.

**`app/presentation/dependencies.py`**

Создаёт один общий `LinkService` с `SqlAlchemyLinkRepository` и отдаёт его
роутам через `Depends`.

### Frontend

**`static/index.html`** — страница просмотра.

**`static/manage.html`** — страница добавления/редактирования.

**`static/contacts.html`** — контакты.

**`static/css/style.css`** — оформление.

**`static/js/api.js`** — общие функции для запросов к API:
`getLinks`, `addLink`, `updateLink`, `deleteLink`, `apiFetch`.

**`static/js/view.js`** — рисует список ссылок и фильтрует по поиску.

**`static/js/manage.js`** — форма, кнопки «Редактировать»/«Удалить», счётчик.

### Docker и запуск

**`Dockerfile`** — как собрать образ приложения.

**`docker-compose.yml`** — как запустить два контейнера: `app` и `db`.

**`requirements.txt`** — Python-библиотеки.

**`README.md`** — инструкция по запуску.

## 5. Почему файлов так много

Можно было бы написать всё в одном `main.py`. Но тогда сложно менять части.

Здесь «луковая архитектура»:

```
presentation  →  application  →  domain
                       ↑
                infrastructure
```

- `domain` — не зависит ни от чего;
- `application` — зависит только от `domain`;
- `infrastructure` — реализует интерфейс из `application`;
- `presentation` — вызывает `application`.

Главная идея: **бизнес-логика не знает, откуда пришли данные и где они
хранятся**. Поэтому замена памяти на PostgreSQL в лабе №3 коснулась в
основном папки `infrastructure`.

На защите это можно сформулировать так:

> Разделил приложение на слои: domain — сущности, application — бизнес-логика,
> infrastructure — работа с PostgreSQL, presentation — HTTP API. Зависимости
> направлены внутрь, поэтому хранилище можно заменить, не меняя логику.

## 6. База данных

СУБД: PostgreSQL 16.

База: `links`.
Пользователь: `links`.
Пароль: `links`.

Таблица `links`:

| Поле | Тип | Смысл |
|---|---|---|
| id | integer, primary key | номер ссылки |
| title | varchar(200) | название |
| url | varchar(500) | адрес |

SQL-аналог:

```sql
CREATE TABLE links (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    url VARCHAR(500) NOT NULL
);
```

Таблица создаётся автоматически при запуске:

```python
Base.metadata.create_all(bind=engine)
```

Это не миграции, а простой способ создать таблицы, если их нет.
Для лабораторной этого достаточно.

Данные лежат в Docker-volume `pgdata`, поэтому после `docker compose down`
и нового `up` ссылки остаются. А `docker compose down -v` удаляет и базу.

### Что такое ORM

ORM — это библиотека, которая позволяет работать с таблицами как с
Python-классами, а не писать SQL руками.

Вместо:

```sql
SELECT * FROM links WHERE id = 1;
```

пишем:

```python
session.get(LinkModel, 1)
```

SQLAlchemy сама превращает это в SQL.

## 7. Docker

### Dockerfile

```dockerfile
FROM python:3.12-slim
ENV PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Построчно:

- `FROM` — взять готовый образ Python;
- `ENV PYTHONUNBUFFERED=1` — сразу показывать `print` в логах;
- `WORKDIR` — рабочая папка внутри контейнера;
- `COPY requirements.txt .` — скопировать список библиотек;
- `RUN pip install` — установить их;
- `COPY . .` — скопировать код проекта;
- `CMD` — команда запуска сервера.

`uvicorn` — сервер, который запускает FastAPI-приложение.
`--host 0.0.0.0` — слушать все адреса внутри контейнера.
`--port 8000` — внутренний порт.

### docker-compose.yml

Два сервиса:

**`db`** — PostgreSQL:

- образ `postgres:16-alpine`;
- база/пользователь/пароль `links`;
- volume `pgdata` для хранения данных;
- `healthcheck` проверяет, что база готова.

**`app`** — наше приложение:

- собирается из `Dockerfile`;
- порт `8080:8000` — снаружи 8080, внутри контейнера 8000;
- переменные окружения:
  - `DATABASE_URL` — адрес базы;
  - `API_KEY` — ключ;
  - `APP_PORT` — только для красивой ссылки в логах;
- `depends_on` — ждать, пока `db` станет healthy.

Почему 8080 снаружи, а 8000 внутри:

- внутри контейнера приложение слушает 8000;
- на компьютер этот порт проброшен как 8080;
- поэтому в браузере открываем `http://127.0.0.1:8080`.

### Команды

```bash
docker compose up --build      # запустить и показывать логи (терминал занят)
docker compose up --build -d   # запустить в фоне
docker compose logs -f app     # смотреть логи
docker compose down            # остановить
docker compose down -v         # остановить и удалить базу
```

`up` без `-d` не зависает. Он специально остаётся в терминале и показывает
логи. Ctrl+C останавливает контейнеры.

## 8. Авторизация

Все методы `/api/links` требуют заголовок:

```
X-API-Key: student-key
```

Ключ задаётся в `docker-compose.yml`:

```yaml
environment:
  API_KEY: student-key
```

И читается в Python:

```python
API_KEY = os.getenv("API_KEY", "student-key")
```

Если ключ не совпал — `401 Unauthorized`.

В Swagger есть кнопка **Authorize**: вводишь ключ, и дальше запросы идут с
ним.

На сайте ключ спрашивается один раз через `prompt()` и сохраняется в
`localStorage` браузера. Поэтому при обновлении страницы его не надо вводить
заново.

Важно: в реальном приложении так делать нельзя, потому что ключ лежит в
JS и его видно в браузере. Для лабораторной это нормально — главное, что
API без ключа не отвечает.

## 9. Чем лаба №3 отличается от лабы №2

В лабе №2 был `InMemoryLinkRepository`: данные лежали в словаре Python.

```python
self.items: dict[int, Link] = {}
```

Плюс: просто. Минус: при перезапуске всё пропадает, и несколько копий
приложения не могут работать с одними данными.

В лабе №3 вместо него `SqlAlchemyLinkRepository`, который пишет в
PostgreSQL. Остальные слои почти не изменились — это и есть польза
архитектуры.

Ещё добавились:

- Dockerfile и docker-compose;
- проверка `X-API-Key`;
- страница `/health`.

## 10. Как реально разобраться (план на вечер)

### 1. Запусти и потрогай API

```bash
docker compose up --build -d
```

Открой `http://127.0.0.1:8080/docs`, нажми **Authorize**, введи
`student-key` и выполни:

1. `GET /api/links` — посмотри список.
2. `POST /api/links` — добавь ссылку.
3. `GET /api/links` — убедись, что появилась.
4. `PUT /api/links/{id}` — измени.
5. `DELETE /api/links/{id}` — удали.

Так ты увидишь, что API работает отдельно от сайта.

### 2. Посмотри запросы в браузере

Открой сайт, нажми `F12` → вкладка **Network** → добавь ссылку.
Найди запрос `POST /api/links` и посмотри:

- URL;
- метод;
- заголовки (там будет `X-API-Key`);
- тело запроса (JSON);
- ответ и код `201`.

Это самое наглядное: видно, как JS общается с Python.

### 3. Читай код в правильном порядке

Не пытайся читать всё сразу. Иди по пути запроса:

1. `main.py` — как всё запускается.
2. `app/presentation/api.py` — какие есть URL.
3. `app/presentation/schemas.py` — что принимаем и отдаём.
4. `app/application/services.py` — какие правила.
5. `app/infrastructure/repository.py` — как работает с базой.
6. `app/infrastructure/models.py` — как выглядит таблица.
7. `static/js/api.js` и `static/js/manage.js` — как сайт вызывает API.

После этого остальные файлы будут понятны сами.

### 4. Поставь print и посмотри порядок

Добавь временно:

```python
# api.py, create_link
print("Пришёл запрос на создание")

# services.py, create
print("Сервис проверяет лимит")

# repository.py, add
print("Репозиторий пишет в базу")
```

Запусти, добавь ссылку и посмотри логи. Ты увидишь, в каком порядке
вызываются слои. Потом print убери.

### 5. Сломай специально

Это лучший способ понять:

- убери `X-API-Key` в Swagger → получишь `401`;
- запроси `/api/links/9999` → `404`;
- добавь 51-ю ссылку → `409`;
- отправь `title` длиной 300 символов → `422`;
- останови контейнер `db` и попробуй добавить ссылку → ошибка базы.

Каждый код ответа станет понятным.

Проверь себя:

- `main.py` — запускает приложение и отдаёт страницы.
- `entities.py` — описывает ссылку.
- `services.py` — проверяет правила.
- `repository.py` — работает с базой.
- `models.py` — описывает таблицу.
- `api.py` — принимает HTTP-запросы.
- `schemas.py` — проверяет JSON.
- `security.py` — проверяет ключ.
- `api.js` — отправляет запросы с сайта.
- `manage.js` — рисует форму и список.
- `Dockerfile` — собирает образ.
- `docker-compose.yml` — запускает приложение и базу.

Если можешь сказать это без подглядывания — база уже есть.

## 11. Вопросы на защите и короткие ответы

**Что такое API?**
Набор URL, по которым программы общаются между собой. У нас это
`/api/links`.

**Что такое REST?**
Стиль API, где действия выражаются HTTP-методами: GET — получить,
POST — создать, PUT — изменить, DELETE — удалить.

**Что такое CRUD?**
Create, Read, Update, Delete — создать, прочитать, изменить, удалить.

**Почему PostgreSQL, а не память?**
Данные сохраняются после перезапуска, их можно хранить много и несколько
клиентов видят одно и то же.

**Что такое ORM?**
Библиотека, которая позволяет работать с таблицами как с Python-классами.
У нас SQLAlchemy.

**Где создаётся таблица?**
В `create_tables()` через `Base.metadata.create_all()` при старте
приложения.

**Что будет с данными после `docker compose down`?**
Останутся, потому что лежат в volume `pgdata`. Удалятся только после
`docker compose down -v`.

**Зачем `X-API-Key`?**
Чтобы API могли использовать только те, кто знает ключ. Без ключа — `401`.

**Почему `401`, а не `403`?**
`401` — не аутентифицирован (ключ неверный/отсутствует). `403` был бы
«аутентифицирован, но нельзя».

**Что значит `404`?**
Не найдено. Например, ссылки с таким `id` нет.

**Что значит `409`?**
Конфликт. У нас — достигнут лимит 50 записей.

**Что значит `422`?**
Ошибка валидации. Например, `title` длиннее 200 символов.

**Почему `201` при создании?**
Создан новый объект.

**Почему `204` при удалении?**
Всё хорошо, но возвращать нечего.

**Чем POST отличается от PUT?**
POST создаёт новую запись, PUT изменяет существующую по `id`.

**Что такое JSON?**
Текстовый формат данных вида `{"title": "ВК", "url": "..."}`.

**Что делает Dockerfile?**
Описывает, как собрать образ приложения.

**Что делает docker-compose?**
Запускает несколько контейнеров вместе: приложение и базу.

**Почему снаружи 8080, а внутри 8000?**
Внутри контейнера приложение слушает 8000, наружу этот порт проброшен
как 8080.

**Что такое слой?**
Часть программы с одной ответственностью. У нас domain, application,
infrastructure, presentation.

**Зачем интерфейс репозитория?**
Чтобы сервис не зависел от конкретной базы. В лабе №2 была память, в
лабе №3 — PostgreSQL, а сервис не менялся.

**Почему сайт не обращается к базе напрямую?**
Браузер не должен знать пароль от базы. Сайт общается только с API.

**Что такое Swagger?**
Автоматическая документация API, где можно выполнять запросы.

## 12. Самое короткое объяснение, что сделано

> Приложение — сайт со ссылками на FastAPI. Код разделён на слои:
> domain описывает ссылку, application содержит правила (лимит 50),
> infrastructure работает с PostgreSQL через SQLAlchemy, presentation
> принимает HTTP-запросы. Данные хранятся в таблице `links`. Приложение и
> база запускаются в Docker через docker-compose. Все методы API защищены
> заголовком `X-API-Key`. По сравнению с лабой №2 хранилище заменили с
> памяти на PostgreSQL, добавили Docker и аутентификацию.

Если преподаватель просит показать код — показывай в таком порядке:
`api.py` → `services.py` → `repository.py` → `models.py`.
Это и есть путь запроса.
